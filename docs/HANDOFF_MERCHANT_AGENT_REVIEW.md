2. 当前产品定位
这个产品不是传统商场运营后台，也不是在后台上叠加一个 AI 助手。

当前已经确认的方向是：

面向商场运营方的“经营问题线程工作台 / 联合研判系统”

一句话理解：

围绕真实经营问题，多个业务 Agent 与总经理在一个线程内持续联合研判、补证据、请示、拉人入会、形成方案、推动执行，并沉淀为组织经验。

中间主区 = 当前议题的联合研判主线程
右侧栏 = 当前议题的上下文、关键依据、待总经理决策信息

5. 角色体系与职责划分
当前 Agent 角色不是按“模型能力”划分，而是按业务职责划分。

核心角色
风险诊断师

负责发现异常
负责风险定级
负责判断是否升级为联合研判
负责定义窗口期、严重程度、是否需要立即介入
商户经营顾问

负责解释经营表现变化
负责分析客单价、消费结构、翻台率、复购等经营根因
负责提出经营改善方向
活动策略师

负责分析活动效果
负责判断流量质量与转化问题
负责提出活动策略或不建议继续活动的判断
巡店督导

负责补充现场体验与执行问题
负责把线下感知带入研判
招商经理

负责从续约策略、商户组合角度给出判断
负责说明哪些经营信号会改变招商侧保留意愿
案例记忆官

负责调取历史案例
负责沉淀新经验
负责说明“这次建议为什么可复用”
任务调度官

负责把方案转成执行任务
负责组织执行动作、责任人、复盘节点
当前重点区分
风险诊断师 和 商户经营顾问 容易混淆，必须继续拉开：

风险诊断师回答：是不是问题、问题有多严重、是否该升级处理
商户经营顾问回答：问题为什么发生、经营上怎么改

8. 当前主要问题
虽然方向对了，但还没达到高完成度，当前最主要的问题有：

8.1 左侧仍偏 inbox，不够像经营事项盘
左侧虽然已经不是旧后台菜单，但仍然更像会话列表 / 消息中心。

目标应该是让总经理一眼看到：

今天最该拍板的是什么
哪些事项卡住了
哪些问题影响续约 / 租金 / 招商 / 客诉 / 活动预算
8.2 中间主线程还是偏“长聊天流”
虽然已经有阶段卡，但还不够强。
总经理仍然需要从长消息里自己归纳。

目标应该是每个阶段更明确地输出：

已确认
仍待确认
需要总经理决定什么
下一步建议
8.3 总经理控制感还不够强
当前已有追问、点名发言等能力，但还不够像“主持联合研判的人”。

需要增强：

指定谁先回答
要求补某类证据
改变研判顺序
暂缓结论
指定研判目标
要求先算 ROI
要求先试点
要求先判断是否值得保留
8.4 请示总经理 / 拉人入会机制还不够闭环
当前“是否邀请招商经理加入”已经出现，但还更像单点剧情。

需要标准化表达：

为什么请示
缺什么信息 / 权限 / 角色
同意后发生什么
新角色加入后修正了什么判断
8.5 方案区还不够像“拍板工具”
当前已有方案对比，但仍偏分析展示。
管理者还需要更直观地判断：

为什么选它
多久见效
是否影响续约判断
成本是否值得
风险在哪里
8.6 右侧上下文区优先级不够清晰
现在右侧信息较全，但应该先服务：

当前待总经理决策事项
当前阶段
本轮研判目标
本轮关键依据
而不是先做资料归档。
